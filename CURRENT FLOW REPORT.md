# Current Affiliate Flow Report (WhereAtlas MVP)

## 1. Overview & Current Click Flow
Currently, WhereAtlas displays travel recommendations based on passport, budget, trip days, and origin. On the Destination Guide page (`/destinations/[id]`), the `BookingCard` component provides two primary outbound Call-to-Actions (CTAs) for users to book flights and hotels:

```
[ User Searches / Enters Destination Guide ]
                   │
                   ▼
  [/destinations/[id] (e.g. /destinations/tokyo)]
                   │
       ┌───────────┴───────────┐
       ▼                       ▼
[ Check Current Flights ]  [ Find Hotels ]
       │                       │
       ▼                       ▼
  Aviasales              Booking.com
```

### Direct Click Paths:
1. **Flight CTA**: `<a href={flightAffiliateUrl(destination, snapshot.origin)} rel="nofollow sponsored">Check Current Flights</a>`
   - Generated by: `flightAffiliateUrl(destination, origin)` in `app/lib/recommendations.ts`
   - Target URL format: `https://search.aviasales.com/flights/?origin_iata={origin.iata}&destination_iata={destination.airportCode}&marker={AVIASALES_MARKER}`
2. **Hotel CTA**: `<a href={hotelAffiliateUrl(destination)} rel="nofollow sponsored">Find Hotels</a>`
   - Generated by: `hotelAffiliateUrl(destination)` in `app/lib/recommendations.ts`
   - Target URL format: `https://www.booking.com/searchresults.html?ss={destination.city}+{destination.country}&aid={BOOKING_AID}`

## 3. Modification Points for Trip.com Affiliate Integration

### Point A: Dedicated Affiliate Resolver Layer (`app/lib/affiliate/`)
- Create `app/lib/affiliate/tripcom-links.ts` containing the verified Trip.com affiliate links (seeded from `scripts/tripcom/output/affiliate-links.json`).
- Create `app/lib/affiliate/index.ts` exporting:
  - `getFlightAffiliateUrl(destinationId: string, originIata?: string): string`
  - `getHotelAffiliateUrl(destinationId: string): string`
- Maintain clean fallback to Aviasales / Booking.com or generic Trip.com search when specific city-pair routes are not yet in the official affiliate database.

### Point B: Connect UI to Resolver (`app/destinations/[id]/page.tsx`)
- Refactor `BookingCard` inside `app/destinations/[id]/page.tsx` to consume `getFlightAffiliateUrl` and `getHotelAffiliateUrl` from `app/lib/affiliate`.
- Convert CTA links to client-enhanced or interactive tracked anchor tags that trigger GA4 events before outbound navigation.

### Point C: GA4 Event Tracking Integration (`affiliate_click`)
- Add a lightweight client tracking component / utility `trackAffiliateClick({ partner, product, destination, origin, passport })`.
- Parameters captured:
  - `partner`: `'trip.com'` (or `'aviasales'` / `'booking.com'`)
  - `product`: `'flight'` | `'hotel'`
  - `destination`: Destination ID/City (e.g. `'tokyo'`)
  - `origin`: Origin IATA / City (e.g. `'LON'`, `'DEL'`)
  - `passport`: Selected passport ID (e.g. `'united-kingdom'`, `'india'`)

### Point D: Alignment with `scripts/tripcom/`
- Ensure `scripts/tripcom/output/affiliate-links.json` can be directly synced/imported or generated with matching keys (`guide_{destination}_{product}`) and standard query parameters (`Allianceid=10173661`, `SID=328960094`, `trip_sub1=...`).
